# Контракт регистрации и входа

В рамках issue #10 определены HTTP-эндпоинты, DTO и правила валидации. `AuthService` сохраняет пользователя, проверяет пароль и выдаёт JWT. Единый формат ошибок относится к отдельной задаче обработки ошибок API.

## Регистрация

`POST /auth/register`, JSON-тело:

```json
{
  "email": "ivan@example.com",
  "password": "secret123",
  "firstName": "Иван",
  "lastName": "Иванов"
}
```

Все поля обязательны. Email должен иметь допустимый формат и длину до 255 символов. Пароль содержит от 8 до 64 символов, хотя бы одну букву и одну цифру. Имя и фамилия &mdash; непустые строки длиной до 100 символов. Аватар пока не принимается.

Успешный ответ: `201 Created` с `userId`, `email`, `firstName` и `lastName`. Пароль в ответ не входит.

## Вход

`POST /auth/login`, JSON-тело с обязательными `email` и `password`. Проверяются формат email и заполненность пароля; правила сложности нового пароля при входе не применяются.

Успешный ответ: `200 OK` с `accessToken` и `tokenType`. Ожидаемое значение `tokenType` &mdash; `Bearer`.

`accessToken` &mdash; JWT, подписанный HS256. Он действует один час и передаётся в заголовке `Authorization: Bearer <accessToken>`. Защищённые маршруты проверяют подпись, издателя и срок действия токена. Сессии на сервере не создаются; выданный токен действует до истечения срока.

Для запуска приложения задайте `AUTH_JWT_SECRET` &mdash; Base64 от случайных 32 байт или более. Для локальной настройки используйте `.env.example` и инструкцию в README. В профиле `dev` допускается запуск без ключа: создаётся временный ключ, поэтому после перезапуска ранее выданные токены перестают действовать. Срок действия можно изменить через `AUTH_JWT_LIFETIME` в формате ISO 8601, например `PT30M`.

## Статусы ошибок по контракту

| Статус | Условие |
| --- | --- |
| `400` | Отсутствует обязательное поле, тело запроса невозможно прочитать или нарушены ограничения валидации |
| `401` | Неверные учётные данные при входе |
| `409` | Email уже занят при регистрации |

Описание этих статусов есть в Swagger. Их единый формат реализуется в задаче обработки ошибок API.
