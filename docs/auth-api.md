# Контракт регистрации и входа

Контракт для issue #10. Здесь описан HTTP-контракт; создание пользователя и проверка токена относятся к задаче бизнес-логики issue #12.

## Регистрация

`POST /auth/register`, `Content-Type: application/json`.

```json
{
  "email": "ivan@example.com",
  "password": "secret123",
  "firstName": "Иван",
  "lastName": "Иванов"
}
```

Все четыре поля обязательны. `avatarUrl` пока не принимается: формат загрузки аватара ещё не определён. По ER-диаграмме `first_name` и `last_name` (почему-то...) допускают `NULL` в базе данных; требование передавать их при регистрации относится к API.

При успехе возвращается `201 Created`. Проект DTO успешного ответа:

```json
{
  "userId": 42,
  "email": "ivan@example.com",
  "firstName": "Иван",
  "lastName": "Иванов"
}
```

`userId` &mdash; целое число. Пароль и его хеш не возвращаются.

## Вход

`POST /auth/login`, `Content-Type: application/json`.

```json
{
  "email": "ivan@example.com",
  "password": "secret123"
}
```

Оба поля обязательны. При верных учётных данных возвращается `200 OK`. Задача бизнес-логики требует выдавать токен доступа; проект DTO ответа:

```json
{
  "accessToken": "<token>",
  "tokenType": "Bearer"
}
```

Формат самого токена и способ хранения сессии артефактами не определены. JSON-схема успешного ответа также является проектным решением. При входе проверяется формат email и заполненность пароля. Правила сложности нового пароля применяются при регистрации; неверный пароль при входе даёт `401`, независимо от его длины и состава.

## Валидация запросов

| Поле | Регистрация | Вход | Правило |
| --- | --- | --- | --- |
| `email` | Обязательно | Обязательно | Строка, допустимый формат email, не более 255 символов по ER-диаграмме; сравнение без учёта регистра |
| `password` | Обязательно | Обязательно | При регистрации 8–64 символа, минимум одна буква и одна цифра; при входе требуется непустое значение |
| `firstName` | Обязательно | Не передаётся | Непустая строка до 100 символов по ER-диаграмме |
| `lastName` | Обязательно | Не передаётся | Непустая строка до 100 символов по ER-диаграмме |

Отсутствующее тело, некорректный JSON или неверный тип значения дают `400` с кодом `MALFORMED_REQUEST`. Отсутствующее обязательное поле, `null`, пустая строка или строка из пробелов дают `400` с кодом `MISSING_FIELD`. Если запрос прочитан и обязательные поля заполнены, но значение не проходит проверку формата или ограничения, возвращается `422` с кодом `VALIDATION_FAILED`.

## Ошибки

Ошибки возвращаются с `Content-Type: application/problem+json`. Тело содержит обязательные поля `type`, `title`, `status`, `detail`, `instance`, `code`, `timestamp`. Для `400` и `422` добавляется массив `errors` с элементами `field` и `message`; `rejectedValue` допускается для других полей, но никогда не возвращается для пароля. `timestamp` имеет формат ISO 8601 с часовым поясом.

| Статус | Код | Условие |
| --- | --- | --- |
| `400 Bad Request` | `MALFORMED_REQUEST` | Нет тела, JSON повреждён или тип поля неверен |
| `400 Bad Request` | `MISSING_FIELD` | Обязательное поле отсутствует или не заполнено |
| `422 Unprocessable Entity` | `VALIDATION_FAILED` | Заполненное поле нарушает правило валидации |
| `401 Unauthorized` | `INVALID_CREDENTIALS` | Email не найден или пароль неверен; одно общее сообщение &laquo;Неверный email или пароль&raquo; |
| `409 Conflict` | `EMAIL_ALREADY_EXISTS` | Email уже зарегистрирован, включая отличие только регистром букв |

При обращении без действительного токена к защищённому эндпоинту используется `401` с кодом `UNAUTHORIZED`. Это поведение реализуется в задаче бизнес-логики.

Пример ошибки валидации регистрации:

```json
{
  "type": "https://rebalance/errors/validation-failed",
  "title": "Некорректные данные",
  "status": 422,
  "detail": "Проверьте поля с ошибками",
  "instance": "/auth/register",
  "code": "VALIDATION_FAILED",
  "timestamp": "2026-11-06T10:15:30+04:00",
  "errors": [
    { "field": "email", "message": "Неверный формат email", "rejectedValue": "ivan.example.com" },
    { "field": "password", "message": "Пароль должен содержать от 8 до 64 символов, хотя бы одну букву и одну цифру" }
  ]
}
```
